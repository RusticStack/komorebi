# Porting the Slint app's tests to the GPUI app

Every test on the Slint app's side (the binary: `src/main.rs`, `src/app.rs`, `src/app/**`,
`src/crash.rs`, `src/format.rs`, `src/rows.rs`), plus the two integration tests that read the
Slint sources (`tests/i18n_catalog.rs`, `tests/shortcuts_table.rs`), and where each goes in
Komorebi 1.0. How the GPUI tests are written: [GPUI-TESTING.md](GPUI-TESTING.md). The library's
own tests (about 735, `src/lib.rs` and below) stay as they are and are not listed.

**The Slint app and its tests were deleted at the cut-over** (docs/GPUI-MIGRATION.md
"Cut-over"). This page is now the record of where each of them went: the file and line columns
point at the deleted sources (`git show 7e53744:<path>` has them), the Status column says whether
the test was ported, moved to the library or dropped as obsolete. A row still marked open is a
test the GPUI app does not have yet; the tests on the calendar (row 43) return with it in 1.1.0.
`tests/shortcuts_table.rs` went with `ui/shortcuts.slint` (its GPUI form is row 36), and
`tests/i18n_catalog.rs` lost its Slint scanner.

## How the table was made

Inventory at gpui/main fdd12cc (line numbers are from that commit), by scanning each `#[test]`
and its body:

- **Kind:** *view-driven* when the test drives `AppWindow` on the headless software-renderer
  platform (`Harness::new`, `MinimalSoftwareWindow`, `set_platform`, `h.ui()`, `h.keys()`,
  `h.app()`); *pixel* when it asserts on rendered pixels (ink counts, tile colours, a raster);
  *source-scan* when it reads `.slint` or catalog sources; otherwise *controller-only* (plain
  logic, no window).
- **Target:** `#[test]` (plain, on a state struct or helper), `#[gpui::test]` (a view through
  GPUI's test context or a headless Kit window with `#[gpui_kit::test]`), or *library* (the code
  is toolkit-free and both apps need it: it moves into the library with its tests, and the
  binary-side copy is deleted).
- **Phase:** the owner phase in [GPUI-MIGRATION.md](GPUI-MIGRATION.md), from the file and then
  from the test's name. It is a first assignment: a phase that finds a test belongs elsewhere
  moves it and says so in its phase notes.
- **What it covers:** the test's doc comment, or its name in words.

Status column.

Notes for the phases:

- **The 4 pixel tests.** The two in `src/main.rs` are the Slint snapshot check's helpers
  (`ink`, `blank_panes`); the GPUI snapshot check has its own (`snapshot::blank_parts` for the
  title bar and the pane, `snapshot::blank_panes` for the list and the reading pane, which came
  back in stage D now that both exist).
  `the_preview_draws_what_is_sent_within_its_caps` renders with the library's raster
  (tiny-skia), so it stays a byte-comparable `#[test]`. `tile_requests_follow_scroll_and_resize`
  counts magenta fake tiles; in GPUI the reader's tile element is asserted on the tiles it
  requests, not on pixels.
- **i18n (phase 15):** `src/app/text.rs` and `tests/i18n_catalog.rs` check the catalog against
  the Slint sources; they are rewritten for the `tr!` macro's sources (REPORT.md S7 i18n
  bridge).
- **`typing_latency_on_a_long_message`** is a timing test on the rich editor (phase 4); it
  keeps its budget in the GPUI editor.
- `opened_messages_are_marked_read_after_the_delay` is the known flaky test (a real 1 s
  timer); its GPUI form uses the test clock and is deterministic.

## Status words

The first word of the Status column says where a row stands: `done` (a GPUI test ported, named),
`moved` (the test went into the library with its code), `covered` (another test checks it),
`partly` and the like (named, with what is left), `to phase N` (waits for a screen), blank (open).
Two words close a row **without a port**, and an integrator counting open rows leaves them out:
`obsolete` (the Slint code it guarded has no GPUI counterpart: rows 82 and 273) and
`not applicable` (the thing it checks does not exist in the GPUI app: rows 150, 152, 229, 230).
Each says why in the row.
